there are two types of transactions
-------------------------------------
1. local transaction
2. global transaction

1.local transactions
---------------------
in local transactions all operations of a transaction are extended on the same database.

example:
funds transfer one account to another account where both accounts belong to the same bank.


2.global transactions
---------------------
in global transactions all operations of a transaction are extended on the different database.

example:
funds transfer one account to another account where both accounts belong to the different bank.


ACID properties
-----------------
Atomicity: all or nothing
consistency: the database remains in a valid state
isolation: transactions do not interface with each other
Durability: committed changes are permanent.



Transaction control language(TCL):
----------------------------------
1. commit
2. rollback
3. save point


1. commit
----------

commit is used to permanently save all changes made during the current transaction into the database

once committed.
--------------
changes become permanent
others users can see the changes
you cannot undo the changes using rollback


2. rollback
-----------
rollback is used to undo all changes made in the current transaction before a commit.

if something goes wrong. rollback restores the database to its previous state.

Introduction to stored procedures
----------------------------------
a stored is a named, precompiled collection of one or more SQL statements that is stored the database and can be
executed called whenever required. instead of sending ling block of SQL from an application every time, he application
simply calls the procedures by name.

why use stored procedures
-------------------------
1. performance
2. reusability
2. reduce network traffic
3. maintainability
4. consistency


advantages
-----------

faster execution after completion
reduce duplicate SQL
support transaction, loops, conditions, variables...etc
easy maintainence


disadvantages
-----------------
debugging can be difficult
vendor specific syntax
complex procedures may become hard to maintain

syntax to create stored procedures
-----------------------------------

delimiter //
create procedure procedure_name()
begin
----SQL statements
end //
delimiter ;

IN parameter
-------------
an IN parameter is used to pass a value into a stored procedure.the procedure can used the value but, changes made to the parameter inside the procedure are not returned to the caller

 syntax
----------
delimiter //
create procedure procedure_name(IN parameter_name datatype)
begin
     SQL stetements
end ;
delimiter ;
